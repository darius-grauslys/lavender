# i32F20_to__i32

**File of origin:** `core/include/numerics.h`

## Semantic

Converts a 20-bit fractional fixed-point number (`i32F20`) to a plain signed 32-bit integer (`Signed_Index__i32`) by performing an arithmetic right shift of 20 bits, effectively discarding the fractional portion.

## Pre-conditions

1. `x` is a valid `i32F20` value (typedef for `int32_t`); any 32-bit signed integer is accepted.
2. No pointer parameters; the function is pure and takes a single value argument.

## Post-conditions

1. Returns the integer portion of the fixed-point input, equivalent to `x / 2^20` with rounding toward zero (truncation of the fractional bits).
2. The return type is `Signed_Index__i32` (typedef for `int32_t`), which matches the input type `i32F20` (`int32_t`) — no type mismatch or truncation.

## Correctness Verdict

**Correct**

## Semantic Alignment

The implementation aligns with the semantic intent. The function uses the `ARITHMETRIC_R_SHIFT` macro, which is explicitly defined to handle right-shifting of negative numbers in a portable, well-defined manner:

```c
#define ARITHMETRIC_R_SHIFT(x, n)\
    (((x)>=0) ? (x) >> (n) : -((-(x)) >> (n)))
```

For positive values, it performs a standard right shift by `FRACTIONAL_PERCISION_20__BIT_SIZE` (20). For negative values, it negates the input, performs the shift, and negates the result — producing correct arithmetic (sign-extending) right shift behavior regardless of compiler-specific semantics for shifting negative values. This is the correct inverse of the companion function `i32_to__i32F20`, which left-shifts by 20 bits via `ARITHMETRIC_L_SHIFT`.

## Implementation Correctness

- **Type compatibility:** Input `i32F20` (`int32_t`) and output `Signed_Index__i32` (`int32_t`) are the same underlying type. The `ARITHMETRIC_R_SHIFT` macro preserves the type throughout. No implicit conversions or truncation occur.
- **Undefined behavior:** The macro avoids implementation-defined behavior from right-shifting negative signed integers by branching on sign. No pointer arithmetic, null dereference, type punning, or out-of-bounds access is present.
- **Validation:** No input validation is needed; the function is a pure arithmetic conversion and any `int32_t` value is a valid `i32F20` input.

## Side Effects

No side effects. This is a pure function with no global state access, no pointer dereferences, and no mutations.
