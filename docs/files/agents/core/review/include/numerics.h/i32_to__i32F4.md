i32_to__i32F4 — core/include/numerics.h

Converts a signed 32-bit integer to a 4-bit fixed-point representation (i32F4) by left-shifting the value by FRACTIONAL_PERCISION_4__BIT_SIZE (4 bits), effectively multiplying the integer by 16.

Pre-conditions:
1. x is a valid Signed_Index__i32 (int32_t). No range constraint is required — any 32-bit signed integer is acceptable as input.
2. The caller is responsible for ensuring the result does not overflow (i.e., x must fit within the representable range of i32F4 after the 4-bit left shift).

Post-conditions:
1. Returns the input value x multiplied by 2^4 (16), expressed in i32F4 fixed-point format. The sign of the input is preserved.
2. The returned i32F4 value is the fixed-point equivalent of the integer input, with the lower 4 bits reserved for fractional precision.

Correctness Verdict: Correct

Semantic Alignment:
The function correctly fulfills its semantic intent of converting a plain signed integer into the i32F4 fixed-point domain. The i32F4 type is defined as int32_t with 4 bits of fractional precision (FRACTIONAL_PERCISION_4__BIT_SIZE = 4), so converting an integer to this format requires multiplying by 2^4, which is achieved via a left shift by 4. The ARITHMETRIC_L_SHIFT macro is used specifically because left-shifting negative signed integers is undefined behavior in C; the macro casts to u32 first, performs the shift on the unsigned value, and casts back to i32, preserving the correct bit pattern for both positive and negative inputs.

Implementation Correctness:
Type compatibility — Signed_Index__i32 (int32_t) is passed to ARITHMETRIC_L_SHIFT which casts it to u32 (uint32_t), shifts, then casts to i32 (int32_t). The return type i32F4 is int32_t, so the final type matches exactly. No implicit conversions or truncation occur.
Undefined behavior — The ARITHMETRIC_L_SHIFT macro avoids the undefined behavior of left-shifting a negative signed integer by first casting to u32. The shift amount (4) is well within the valid range (0–31) for a 32-bit type. No null pointer dereference, no type punning, no out-of-bounds access.
Validation — No validation is needed. This is a low-level conversion function; it is the caller's responsibility to ensure the input does not cause overflow when shifted.

Side Effects:
No side effects — the function is pure. It performs a bitwise computation on its input and returns a value without modifying any state or external objects.
