## 1. Header
- **Function name:** `PLATFORM_release_texture`
- **File of origin:** `core/include/platform.h` (declared at line 156; falls under the `// TODO: remove` block that also contains `PLATFORM_use_texture`)
- **Signature (header, `core/include/platform.h:156-158`):**
  ```c
  void PLATFORM_release_texture(
          PLATFORM_Gfx_Context *p_PLATFORM_gfx_context,
          Texture texture);
  ```
- **Core type (`core/include/defines.h:754-757`):** `Texture` is the by-value wrapper struct `{ PLATFORM_Texture *p_PLATFORM_texture; Texture_Flags texture_flags; }`. Only `p_PLATFORM_texture` (a `PLATFORM_Texture *`) is read by this function; `texture_flags` is not inspected.
- **Implementations:**
  - Canonical (SDL/GL): `sdl/source/rendering/sdl_texture_manager.c:170` — unwraps `texture.p_PLATFORM_texture` and forwards to `SDL_release_texture`, which (1) calls the sub-context hook `f_SDL_operate_texture` bound to `GL_release_texture` (`sdl/source/rendering/sdl_gfx_context.c:131-133` → `sdl/source/rendering/opengl/gl_texture.c:216`), i.e. `glDeleteTextures(1, &p_PLATFORM_texture->GL_texture_handle)`, then (2) calls `SDL_release_texture_from__texture_manager` (`sdl/source/rendering/sdl_texture_manager.c:66`) which validates the handle's pool membership and runs `DEALLOCATE_P(p_PLATFORM_texture)` (`core/include/serialization/serialization_header.h:55`), i.e. `initialize_serialization_header_for__deallocated_struct` — Lavender-style pool-reset, **not** RAII resource acquisition.
  - Conforming stubs: `no_gui/source/NOT_IMPL.c:32` (empty body, signature matches header) and `tests/core/source/PLATFORM.c:247` / `tests/templates/source/PLATFORM.c:247` (empty body, signature matches header).
  - **Conflicting (NDS):** `nds/source/rendering/nds_texture_manager.c:76` — defines the 2nd parameter as `PLATFORM_Texture *texture` instead of `Texture texture`. See §7.
- **Note:** the prior file content ("no implementation found") is stale; multiple implementations exist (header + SDL/no_gui/test-stub + NDS).
- **Documented contract:** `agents/platform_api.md:284-288` lists the SDL (`sdl_texture_manager.c:170`) and NDS (`nds_texture_manager.c:76`) implementations and describes the behavior as "Frees a backend texture resource."

## 2. Semantic
Releases (frees) a backend/GPU texture resource owned by the core `Texture` wrapper. The `Texture` is passed by value; the backend reads only the embedded `p_PLATFORM_texture` pointer and disposes of the underlying platform handle (SDL/GL: `glDeleteTextures`) and the pool slot it occupies (`DEALLOCATE_P`). Returns void. It is the resource-disposing counterpart of `PLATFORM_allocate_texture`/`PLATFORM_allocate_texture_with__path`: whoever allocates a texture must later call this to avoid leaking the backend handle and pool slot. Marked `// TODO: remove` alongside its sibling bind call `PLATFORM_use_texture` (`platform_api.md:685` — texture binding/use/disposal intended to be inlined into sprite/world render calls).

## 3. Pre-conditions
1. `p_PLATFORM_gfx_context` is non-null and points to a valid, already-initialized platform graphics context whose `SDL_gfx_sub_context__wrapper.f_SDL_release_texture` sub-context hook has been bound (to `GL_release_texture` in the SDL/GL backend).
2. `texture.p_PLATFORM_texture` is non-null and points to a valid, previously-allocated `PLATFORM_Texture` whose backend handle is live and that was allocated from the context's texture pool (so the pointer-arithmetic index in `SDL_release_texture_from__texture_manager` is well-defined).
3. The `Texture` value is a shallow copy whose `p_PLATFORM_texture` still aliases the caller's underlying `PLATFORM_Texture` object; `texture_flags` is ignored.
4. The backend handle has not already been released (i.e. this is not a double-release); the SDL path's `SDL_release_texture_from__texture_manager` bounds-checks the handle against the pool, but there is no "already deallocated" guard analogous to the NDS backend's `is_texture_flags__allocated` check.
5. This is **not** an initialization/RAII function: it performs no struct cleaning of a `Texture` to a default state — it frees a backend resource and resets the *platform* struct to a deallocated pool slot. (The caller, e.g. `aliased_texture_manager.c:313,334,354`, performs any subsequent Lavender-style `initialize_aliased_texture` on the owning `Aliased_Texture`; that is out of this function's scope.)

## 4. Post-conditions
1. The backend texture resource is released (SDL/GL: the GL texture object is deleted via `glDeleteTextures`, releasing driver-side texture-unit state; the no_gui/test stubs do nothing).
2. The `PLATFORM_Texture` pool slot backing `texture.p_PLATFORM_texture` is reset to the deallocated state via `DEALLOCATE_P` (= `initialize_serialization_header_for__deallocated_struct`), so it is eligible for reuse/return to the free pool by the allocator.
3. Returns void. `p_PLATFORM_gfx_context` is dispatched-through but not structurally mutated; the `Texture` value parameter is not mutated (only `texture.p_PLATFORM_texture` is read).
4. On the SDL/GL path: if `glDeleteTextures` raises a GL error, it is reported via `debug_error` ("SDL::GL::PLATFORM_release_texture failed. (glDeleteTextures)") and the function returns; the pool deallocation (`DEALLOCATE_P`) still follows, so the slot is reclaimed even if the GPU deletion reported an error (no compensating revert).
5. The no_gui/test stubs leave the backend (and the `Texture`) untouched (no-op).

## 5. Correctness Verdict
Incorrect

## 6. Semantic Alignment
The canonical SDL/GL implementation fulfills the semantic intent: it extracts the platform handle from the by-value `Texture`, deletes the GPU texture object (`glDeleteTextures`), and reclaims the pool slot (`DEALLOCATE_P`), matching the "free a backend texture resource" intent and the documented contract in `agents/platform_api.md:288`. The header and the SDL/no_gui/test-stub implementations are all mutually consistent and semantically correct.

However, the **NDS implementation** (`nds/source/rendering/nds_texture_manager.c:76-109`) violates the contract in both *intent* and *form*: it declares the second parameter as `PLATFORM_Texture *texture` (the platform-specific struct pointer) rather than the core wrapper `Texture texture` by value. Its body dereferences `texture->oam`, `texture->gfx`, `texture->oam_index`, etc. — members of the NDS `PLATFORM_Texture` — which is semantically plausible for the NDS backend, but it cannot be invoked by any caller that conforms to the `platform.h` prototype (which passes a `Texture` by value), because the ABI/C type contract is broken. As with the sibling functions `PLATFORM_use_texture` and `PLATFORM_allocate_texture`, this makes the NDS backend non-conformant to the platform API contract, so the function as a whole (header + all backends) is incorrect.

## 7. Implementation Correctness
- **Type compatibility (canonical / SDL / stubs):** The header declaration and the SDL, no_gui, and test-stub definitions all match exactly — `void f(PLATFORM_Gfx_Context *, Texture)`. In the SDL path, `texture.p_PLATFORM_texture` has type `PLATFORM_Texture *` (per `defines.h:755`), which is forwarded to `SDL_release_texture`'s parameter `PLATFORM_Texture *p_PLATFORM_texture` (`sdl/source/rendering/sdl_texture_manager.c:47`) and onward to the sub-context hook `f_SDL_release_texture`, whose typedef is `void (*f_SDL_release_texture)(PLATFORM_Texture *)` (`sdl/include/sdl_defines.h` / the `f_SDL_release_texture` member at `sdl/include/sdl_defines.h:257`). Exact match at every link, no implicit conversions, no truncation. The test stubs match the header verbatim.
- **Conflicting types (NDS backend):** `nds/source/rendering/nds_texture_manager.c:76` defines
  ```c
  void PLATFORM_release_texture(
          PLATFORM_Gfx_Context *p_PLATFORM_gfx_context,
          PLATFORM_Texture *texture) { /* ... reads texture->oam, texture->gfx ... */ }
  ```
  while this same translation unit includes `core/include/platform.h` (line 3) and `core/include/defines_weak.h` (line 2, which forward-declares `typedef struct Texture_t Texture;` at `defines_weak.h:382`), yielding the header prototype `void PLATFORM_release_texture(PLATFORM_Gfx_Context *, Texture)` in scope. The NDS type `PLATFORM_Texture *` (`struct PLATFORM_Texture_t *`, declared `typedef struct PLATFORM_Texture_t PLATFORM_Texture_t;` at `platform.h:449`, completed in `nds/include/nds_defines.h`) is an incompatible type with the core wrapper `Texture` (`struct Texture_t`), so this is a **C11 6.7p4 constraint violation ("conflicting types for 'PLATFORM_release_texture'")** — a hard error under the NDS `-Wall` flags (`nds/Makefile:17`). This is the **same defect class** already documented for `PLATFORM_use_texture` (`agents/core/review/include/platform.h/PLATFORM_use_texture.md` §7) and `PLATFORM_allocate_texture` (`agents/core/review/include/platform.h/PLATFORM_allocate_texture.md` §7), and the analogous `PLATFORM_allocate_sprite` pattern. Because the function is actually *used* in the NDS body (it dereferences `texture->oam`/`texture->gfx`/`texture->oam_index` rather than being a no-op), a non-conforming compiler that did link it would also exhibit **undefined behavior at runtime**: the by-value `Texture` argument (per the header ABI) would be reinterpreted as a `PLATFORM_Texture *`, so `texture->oam` etc. would read from the `Texture.p_PLATFORM_texture` pointer slot as if it were a `PLATFORM_Texture *` — producing garbage/dereferenced-null. (On the canonical SDL path there is no such reinterpretation: `texture.p_PLATFORM_texture` is explicitly field-selected, which is correct.)
- **Build composition / cross-TU conflict (NDS):** The NDS Makefile (`nds/Makefile:67`) builds `CFILES := $(CFILES_NDS) $(CFILES_CORE)` and links `$(OFILES_CORE) $(OFILES_NDS)` (`nds/Makefile:96`). The shared-core sources `core/source/rendering/aliased_texture_manager.c` (call site at `aliased_texture_manager.c:310,331,351`, passing `p_aliased_texture->texture`, a `Texture`) and `core/source/rendering/sprite_manager.c` (call site at `sprite_manager.c:127`) are compiled into the NDS binary and both invoke `PLATFORM_release_texture` with the header's 2-argument `(ptr, Texture)` signature. Those core TUs see only the `platform.h` prototype and emit conforming 2-arg call sites; the NDS TU defines a 2-arg-but-different-type variant. This is the identical link-time/constraint hazard documented for the sibling texture functions; it makes the NDS backend uncompilable as written and, transitively, unsound for any build that links core callers against the NDS definition.
- **Undefined behavior (canonical / SDL path):** No UB on the happy path. `SDL_release_texture` dereferences `p_PLATFORM_gfx_context` and `GL_release_texture` dereferences `p_PLATFORM_texture->GL_texture_handle` with no null-check of `p_PLATFORM_texture`; per Lavender's convention these are caller preconditions and the pattern is consistent with the sibling `SDL_use_texture` / `SDL_allocate_texture` wrappers (see `PLATFORM_use_texture.md` §7 and `PLATFORM_allocate_texture.md` §7). No broken pointer arithmetic, no type punning, no out-of-bounds. (Note: `SDL_release_texture_from__texture_manager` computes `u16 index = p_PLATFORM_texture - SDL_textures` before its bounds check — this is valid pointer arithmetic *only* if `p_PLATFORM_texture` actually points into the `SDL_textures` pool array; that is a caller precondition, not an in-function check, and matches the engine's pool-handle contract.)
- **Validation appropriateness:** No in-function pointer validation on the canonical path — consistent with the engine's PAL pattern where validation is the caller's responsibility at the platform boundary. The `// TODO: remove` marker signals the function is deprecated/architected-for-removal, so adding defensive checks here would be wasteful; the real fix is to eliminate the function and inline its disposal into sprite/world render calls (`platform_api.md:685`), as is done for `PLATFORM_use_texture`/`PLATFORM_update_texture`.
- **Validation asymmetry:** Note the NDS body *does* carry two debug guards (`is_texture_flags__allocated` → "double free." debug_error; pool-index bounds → "not allocated with this NDS_Texture_Manager.") and the SDL path's `SDL_release_texture_from__texture_manager` *does* bounds-check the pool index, but neither guards an actual double-`glDeleteTextures` (the NDS guards check the *texture manager* allocation flags, not whether the GL handle itself was already deleted). This is a latent weakness but is shared by the resource-management design and is out of scope for a single-function review.
- **Resource ownership / double-free:** On both backends, `texture.p_PLATFORM_texture` is read and the owned handle + pool slot are freed; the `Texture` value parameter itself is not freed/dealloc'd (it is caller-owned and only its `p_PLATFORM_texture` target is released). A second call with the same released handle is a caller error (double release).
- **Lavender init semantics:** Not an initializer. `DEALLOCATE_P` resets the *platform struct* to a deallocated pool state (Lavender-style "init = pool cleanup"), but that is a side effect on the `PLATFORM_Texture` slot, not a caller-facing "initialization" of a core `Texture` — and this function does not touch the core `Texture` at all (it's a by-value copy, never written back). The `initialize_*texture` calls seen in call sites (`aliased_texture_manager.c:313`) are the caller's responsibility and out of scope.

## 8. Side Effects
- **GPU:** Deletes the backend texture object — SDL/GL: `glDeleteTextures(1, &p_PLATFORM_texture->GL_texture_handle)` via the `f_SDL_release_texture` → `GL_release_texture` dispatch chain; mutates driver-side GL texture-unit state. If `glDeleteTextures` raises a GL error, a `debug_error("SDL::GL::PLATFORM_release_texture failed. (glDeleteTextures)")` message is emitted; the pool reclamation below still proceeds.
- **Pool:** Reclaims the `PLATFORM_Texture` slot backing `texture.p_PLATFORM_texture` by calling `DEALLOCATE_P(p_PLATFORM_texture)` — i.e. `initialize_serialization_header_for__deallocated_struct`, resetting the slot to the deallocated/initial state so it can be returned to the free pool for reuse. (No_gui/test stubs: no side effects.)
- **Does not** mutate `p_PLATFORM_gfx_context` (dispatch only), does not mutate the `Texture` value parameter (only reads `texture.p_PLATFORM_texture`), and does not modify `texture_flags`.
- **NDS backend (as written):** reads `texture->oam`, `texture->oam_index`, `texture->gfx`, and the texture-manager's texture flags; if the constraint violation were bypassed it would also misinterpret the by-value `Texture` ABI as a `PLATFORM_Texture *` — UB. (Not a "side effect" of the conformant path; documented for completeness per the defect.)

## 9. Issues Summary
1. **NDS backend signature mismatch (Incorrect):** `nds/source/rendering/nds_texture_manager.c:76` defines the second parameter as `PLATFORM_Texture *texture`, conflicting with the `platform.h` prototype `Texture texture` visible in the same translation unit. This is a C11 6.7p4 constraint violation (hard error under `nds/Makefile:17` `-Wall`) and is the same defect class documented for `PLATFORM_use_texture` and `PLATFORM_allocate_texture`. The canonical SDL/no_gui/test-stub implementations are conformant and correct. Recommended fix: bring the NDS definition in line with the header (`Texture texture`, then read `texture.p_PLATFORM_texture`) so it can be invoked by the existing core call sites (`aliased_texture_manager.c:310,331,351`; `sprite_manager.c:127`) — or, given the `// TODO: remove` intent, inline disposal into the sprite/world render path and drop the function entirely.
