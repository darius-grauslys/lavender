i32_to__i32F8 — core/include/numerics.h

Converts a signed 32-bit integer (whole number) to an i32F8 fixed-point representation with 8 bits of fractional precision by left-shifting the two's complement bit pattern by 8 bits.

Pre-conditions:
1. x must be a valid Signed_Index__i32 (int32_t); no range constraint — the function accepts the full int32_t range.

Post-conditions:
1) The return value is an i32F8 where the integer value of x is scaled by 2^8 (256), representing x as a fixed-point number with 8 fractional bits. For example, 1 → 256, -1 → -256.

Correctness Verdict: Correct

Semantic Alignment:
The function correctly converts a whole-number i32 to an i32F8 fixed-point value with 8 bits of fractional precision. The implementation follows the same pattern as i32_to__i32F4 and i32_to__i32F20, which are the sibling functions for 4-bit and 20-bit fractional precision respectively. All three use ARITHMETIC_L_SHIFT with their respective FRACTIONAL_PERCISION_*.__BIT_SIZE constants.

Implementation Correctness:
Type compatibility — the parameter type Signed_Index__i32 (int32_t) is compatible with the ARITHMETIC_L_SHIFT macro which casts to u32 for the shift, then back to i32. The return type i32F8 is also int32_t, so no truncation occurs.
No undefined behavior — ARITHMETIC_L_SHIFT explicitly handles negative numbers by casting to u32 first (two's complement reinterpretation), which is well-defined in C for signed-to-unsigned conversion within the same width. The left shift on a u32 is also well-defined. No null dereference or out-of-bounds access.
No validation is needed — this is a low-level type conversion function. The caller is responsible for ensuring x is a valid Signed_Index__i32.

Side Effects:
No side effects — the function is pure; it only returns a computed value based on the input parameter.
