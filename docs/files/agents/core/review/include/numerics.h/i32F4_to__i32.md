# i32F4_to__i32

**File of origin:** `core/include/numerics.h`

## Semantic

Converts a 32-bit fixed-point value with 4 fractional bits (`i32F4`) to a plain signed 32-bit integer (`Signed_Index__i32`) by performing an arithmetic right shift of 4 bits, effectively dividing by 2^4 = 16 and truncating the fractional part.

## Pre-conditions

1. The input parameter `x` is of type `i32F4` (which is a typedef for `int32_t`), representing a signed 32-bit fixed-point number with 4 fractional bits.
2. The shift constant `FRACTIONAL_PERCISION_4__BIT_SIZE` is defined as `4` and is a valid shift amount for a 32-bit integer (0–31 range).
3. The macro `ARITHMETRIC_R_SHIFT` is defined and handles both positive and negative values of `x` correctly.

## Post-conditions

1. The function returns a `Signed_Index__i32` (typedef for `int32_t`) representing the integer portion of the fixed-point input.
2. For non-negative inputs, the result equals `x >> 4` (integer division by 16, truncating toward zero).
3. For negative inputs, the result is computed as `-((-(x)) >> 4)`, which correctly performs an arithmetic right shift on the original negative value, preserving the sign and truncating toward zero.
4. The conversion is the inverse of `i32_to__i32F4` for the integer portion (i.e., `i32F4_to__i32(i32_to__i32F4(n))` yields `n` for any `Signed_Index__i32` value `n` that does not overflow when left-shifted by 4).

## Semantic Alignment

The implementation fulfills its semantic intent. The function correctly converts a 4-bit fractional fixed-point integer to a plain signed integer by performing an arithmetic right shift by 4 bits. The `ARITHMETRIC_R_SHIFT` macro is used specifically to address the C language's implementation-defined behavior for right shifts of negative signed integers. By branching on the sign of `x` and always performing the shift on a positive value (then negating the result for negative inputs), the macro ensures consistent arithmetic right shift behavior across all platforms and compilers.

The conversion accurately divides the fixed-point value by 16 (2^4), discarding the 4 least significant fractional bits. This is the standard and correct way to convert from a fixed-point representation back to an integer.
