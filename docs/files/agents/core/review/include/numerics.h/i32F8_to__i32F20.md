# i32F8_to__i32F20

**File of origin:** `core/include/numerics.h`

## Semantic

Converts a fixed-point value with 8 fractional bits (`i32F8`) to a fixed-point value with 20 fractional bits (`i32F20`) by left-shifting the raw integer representation by 12 bits (the difference between 20 and 8 fractional bit counts).

## Pre-conditions

1. `x` is a valid `i32F8` value (an `int32_t` with 8 bits of fractional precision). No null or pointer constraint applies; the parameter is passed by value.
2. The caller is responsible for ensuring the left shift by 12 bits does not cause overflow beyond the representable range of `int32_t`. If the input magnitude is too large, the result will overflow silently (no saturation or clamping is performed).

## Post-conditions

1. The function returns a `Signed_Index__i32` (i.e., `int32_t`) whose value equals the input bit-pattern left-shifted by 12 positions, interpreted as a fixed-point number with 20 fractional bits.
2. The arithmetic left shift is performed via `ARITHMETRIC_L_SHIFT`, which casts the signed input to `u32` before shifting and casts the result back to `i32`, avoiding the undefined behavior of left-shifting negative signed integers.

## Correctness Verdict

**Correct**

## Semantic Alignment

The implementation correctly fulfills its semantic intent. Converting from an F8 to an F20 fixed-point format requires shifting the raw integer left by (20 − 8) = 12 bits, which is exactly what the function does using `FRACTIONAL_PERCISION_12__BIT_SIZE` (defined as 12). This is consistent with the sibling conversion functions in the same file (e.g., `i32F20_to__i32F8` right-shifts by 12, `i32F4_to__i32F20` left-shifts by 16, etc.). The use of `ARITHMETRIC_L_SHIFT` ensures the shift is well-defined for negative values.

## Implementation Correctness

- **Type compatibility:** The parameter `x` is of type `i32F8` (i.e., `int32_t`). The `ARITHMETRIC_L_SHIFT` macro accepts `x` and internally casts it to `u32` for the shift, then casts the result to `i32`. The function's declared return type is `Signed_Index__i32` (i.e., `int32_t`), which matches the `i32` result of the macro. No implicit conversions or truncation occur.
- **Undefined behavior:** The macro `ARITHMETRIC_L_SHIFT` explicitly avoids the undefined behavior of left-shifting negative signed integers by first casting to `u32`. The shift amount (12) is well within the valid range for a 32-bit type. No null pointer dereference or out-of-bounds access is possible.
- **Validation:** No input validation is performed. This is appropriate for a low-level numeric conversion helper; overflow checking is the caller's responsibility, consistent with the other fixed-point conversion functions in this file.

## Side Effects

No side effects. This is a pure function: it reads its input parameter, performs a bitwise shift, and returns the result. No global state is modified, no memory is accessed through pointers, and no I/O occurs.
