# i32F8_to__i32

**File of origin:** `core/include/numerics.h`

## Semantic

Converts an 8-bit fixed-point integer (`i32F8`) to a plain signed 32-bit integer (`Signed_Index__i32`) by performing an arithmetic right shift by 8 bits, effectively dividing the fixed-point value by 256 (2^8).

## Pre-conditions

1. The parameter `x` is of type `i32F8` (which is `typedef int32_t i32F8`), so it is a signed 32-bit integer with 8 bits of fractional precision. No null or range constraints apply — any valid `i32F8` value is accepted.

## Post-conditions

1. The function returns a `Signed_Index__i32` (which is `typedef int32_t Signed_Index__i32`), representing the integer portion of the fixed-point value.
2. The result is the mathematical equivalent of `x / 256` with truncation toward zero for the fractional bits, computed via arithmetic right shift (which preserves the sign bit for negative values).

## Correctness Verdict

**Correct**

## Semantic Alignment

The implementation correctly fulfills its semantic intent. `i32F8_to__i32` is the inverse of `i32_to__i32F8` (which left-shifts by 8 bits to introduce 8 bits of fractional precision). This function right-shifts by 8 bits to remove the fractional precision and recover the integer value. The use of `ARITHMETRIC_R_SHIFT` ensures correct behavior for negative numbers, as plain right shift on signed negative integers is implementation-defined in C. The conversion matches the fixed-point arithmetic convention used throughout the file (F8 denotes 8 fractional bits).

## Implementation Correctness

- **Type compatibility:** The parameter `x` is of type `i32F8` (aliased to `int32_t`), and the return type is `Signed_Index__i32` (aliased to `int32_t`). Both are the same underlying type, so there are no implicit conversions or truncation issues. The shift amount `FRACTIONAL_PERCISION_8__BIT_SIZE` is a constant (8), which is within the valid range for shifting a 32-bit integer.
- **Undefined behavior:** No undefined behavior is present. The `ARITHMETRIC_R_SHIFT` macro handles negative values explicitly by negating, shifting, and re-negating, avoiding the implementation-defined behavior of right-shifting negative signed integers. There is no pointer arithmetic, no null dereference, no type punning, and no out-of-bounds access.
- **Validation:** No validation is needed — the function is a pure numeric conversion with no preconditions beyond the input being a valid `i32F8` value. The lack of validation is appropriate for this low-level utility function.

## Side Effects

No side effects. This is a pure function: it takes an `i32F8` value as input and returns a `Signed_Index__i32` value without modifying any global state, memory, or I/O.
